CX Copilot API

Endpoints for the support inbox: list tickets, run Copilot on a ticket, and record the agent's decision.

Base path /api/cxJSON in and outVersion 1 · 3 October 2026

Overview

  • Base URL (local): http://127.0.0.1:8000. Start the server with uvicorn backend.main:app --reload.
  • Interactive docs: /docs (Swagger) on the running server, generated from the same code as this page.
  • Authentication: none in the MVP. Don't expose the server publicly without adding it.
  • Ticket references: any {ticket_ref} accepts the ticket UUID or its number, such as TKT200001.
  • Dates: ISO 8601. Dates are 2026-10-04; timestamps are 2026-10-03T09:48:00.
  • Money: rupees as numbers, such as 1436.0. Format them in the UI.

All examples on this page are real responses from the demo dataset with no API key set, so they come from the template fallback. With a key, draft is written by Claude and fallback_mode is false; every field keeps the same shape.

Typical flow

sequenceDiagram
  participant UI as Inbox screen
  participant API as /api/cx
  UI->>API: GET /tickets?status=OPEN
  API-->>UI: ticket list
  UI->>API: GET /tickets/TKT200001
  API-->>UI: ticket + order + facts
  UI->>API: POST /tickets/TKT200001/analyze
  API-->>UI: CopilotResult (draft or reason)
  Note over UI: Agent approves, edits or escalates
  UI->>API: POST /tickets/TKT200001/decision
  API-->>UI: new ticket status

Ticket status

stateDiagram-v2
  [*] --> OPEN
  OPEN --> DRAFTED: analyze returns DRAFTED or NEEDS_INFO
  OPEN --> OPEN: analyze returns NEEDS_HUMAN
  DRAFTED --> DRAFTED: analyze again
  OPEN --> RESOLVED: decision APPROVED / EDITED
  DRAFTED --> RESOLVED: decision APPROVED / EDITED
  OPEN --> ESCALATED: decision REJECTED / ESCALATED
  DRAFTED --> ESCALATED: decision REJECTED / ESCALATED
  RESOLVED --> [*]
  ESCALATED --> [*]

Resolved and escalated tickets are closed. Analysing them again returns 409 TICKET_CLOSED.

Data and AI modes

Setting in .envIf setIf blank
SUPABASE_URL + SUPABASE_SERVICE_KEYReads and writes the live Supabase tablesUses 10 demo tickets in memory. Changes are lost on restart.
ANTHROPIC_API_KEYClaude classifies, drafts and checks (Haiku 4.5 + Opus 5.5)Keyword matching and template replies. Results have fallback_mode: true.
CX_TODAYDelays are computed as if today were this dateReal today. In demo mode, 2026-10-03.

Show fallback mode in the UI. When fallback_mode is true, show a banner such as "AI unavailable: using standard replies". The API can switch mid-run if Claude becomes unreachable. notes says why.

Shows whether the database is reachable, whether Claude is set up, and which policy documents loaded. Call it on app start so the UI can warn early.

POST/api/cx/tickets/{ticket_ref}/analyze

Runs Copilot on the ticket: classify, find the order, apply rules, draft, check. Logs the run and sets the ticket to DRAFTED when a reply is ready. No request body.

Takes about 3–6 seconds with Claude and is instant in fallback mode. Show progress while it runs. Calling it again creates a new result; the latest one is what last_result returns.

Errors

404 TICKET_NOT_FOUND · 409 TICKET_CLOSED · 503 DB_ERROR

POST/api/cx/tickets/{ticket_ref}/decision

Records what the agent did with a Copilot result and closes the ticket. Nothing is sent to the customer yet; in the MVP this endpoint only saves the decision.

Request body

FieldTypeRequiredNotes
interaction_idstringyesFrom the analyze result. It must belong to this ticket.
actionstringyesAPPROVED, EDITED, REJECTED or ESCALATED
final_replystringfor EDITEDThe text the agent will send. Ignored for other actions.

POST/api/cx/analyze

Runs Copilot on pasted text without a ticket. Useful for a "try it" box in a demo. The run is logged with no ticket, and no ticket status changes.

Request body

FieldTypeRequiredNotes
messagestringyes1–4,000 characters
order_numberstringnoAdded to the message so Copilot can find the order
customer_idstringnoIf set, an order number belonging to someone else returns NEEDS_HUMAN

GET/api/cx/metrics

Numbers for the CX metrics screen, built from the saved Copilot runs and ticket statuses.

Response 200

{
  "tickets_by_status": { "OPEN": 8, "DRAFTED": 1, "RESOLVED": 1, "ESCALATED": 0 },
  "analysed": 4,                                   // Copilot runs saved
  "by_intent": { "WISMO": 3, "DELIVERED_NOT_RECEIVED": 1 },
  "by_result": { "DRAFTED": 2, "NEEDS_HUMAN": 1, "NEEDS_INFO": 1 },
  "human_actions": { "EDITED": 1 },
  "acceptance_rate": 0.0,                          // APPROVED ÷ (APPROVED + EDITED + REJECTED); null if none
  "fallback_runs": 4,
  "avg_latency_ms": 0,
  "avg_cost_usd": 0.0,
  "total_cost_usd": 0.0
}

In Supabase mode, the 1,200 synthetic rows already in ai_interactions count too. They have an intent but no cost.

Errors

Every error has the same shape:

{ "error": { "code": "TICKET_NOT_FOUND", "message": "No ticket TKT999999" } }

Validation errors (422) add details, one entry per bad field:

{ "error": { "code": "INVALID_REQUEST",
             "message": "interaction_id: Field required; action: Input should be 'APPROVED', 'EDITED', 'REJECTED' or 'ESCALATED'",
             "details": [ { "field": "interaction_id", "problem": "Field required" },
                          { "field": "action", "problem": "Input should be 'APPROVED', 'EDITED', 'REJECTED' or 'ESCALATED'" } ] } }
